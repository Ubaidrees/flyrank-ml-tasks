Predicting Content Decline: An Honest-Validation Case Study

What happens when a real model is checked against a real baseline, on a split that can't cheat — and what breaks along the way when the data itself is checked just as hard.

Muhammad Ubaid Idrees Repository ↗ Data: FlyRank ML Internship ↗
Abstract

This study asks whether search-performance signals — impressions, ranking position, click-through rate, and content freshness — can predict which pages are likely to decline in visibility, well enough to prioritize a content team's limited review capacity. A Random Forest classifier was trained on 30,000 real content records from the FlyRank ML Internship dataset, using twelve portfolio-level features, and compared against a hand-audited baseline rule under a client-grouped validation split that holds entire client portfolios out of training. Two real data-quality issues were found and corrected during the audit before any result was trusted: a click-through-rate unit-scale bug affecting 1,689 rows, and a bulk-update artifact distorting freshness signals for 55.8% of all rows. Under the honest, client-grouped split the model reached an AUC of 0.604; a naive split that allowed client overlap would have overstated this by fourteen points (AUC 0.745), a gap treated here as a finding in its own right rather than a footnote. The result is a modest, real, decision-support signal — not a high-confidence prediction — packaged into a ranked, reason-coded action queue with explicit human-review and no-go rules.

01 Introduction

Content teams managing large portfolios cannot manually review every page every cycle. A prioritization signal — some ranking of "review this first" — is only useful if it is honest about how much better it is than what a team could already build by hand: a simple, transparent rule based on staleness and click performance.

This paper documents that comparison directly: a hand-written baseline rule, audited signal by signal, against a trained model, evaluated under a validation design that cannot let the model quietly memorize client-specific patterns. The emphasis throughout is on what the evidence actually supports, not on the most impressive-sounding number available.

02 Data

This work uses the FlyRank ML Internship starter release (content_refresh_anonymized.csv), a single historical snapshot of portfolio-level content performance. After filtering to active content — impressions_90d > 0 and content_age_days >= 90 (excluding pages too new to have a meaningful trend) and removing duplicate content IDs — 30,000 rows remained for analysis.

Earlier stages of this project also queried the full FlyRank internship warehouse (a Hugging Face–hosted release spanning ~79 million daily performance rows across 104 anonymized clients) to verify data-contract assumptions — grain, availability, and tracking-start dates — before settling on the vetted starter release for modeling, for tractability within the project timeline.

Excluded by design: rows from clients without confirmed search/analytics tracking access; content younger than 90 days (insufficient history for a trend label); any row-level client names, raw URLs, or private query text — all identifiers in this dataset and paper are anonymized hashes.

03 Methodology

Label definition

is_declining_label = 1 if trend_direction == "down", where trend direction is defined (per FlyRank's own published methodology) as a >10% decline in impressions over the trailing 30 days versus the prior 30 days.

Features

Twelve portfolio-level features were used: impressions_90d, clicks_90d, sessions_90d, ai_sessions_90d, content_age_days, days_since_last_update, ctr, avg_position, engagement_rate, scroll_rate, word_count, ai_traffic_pct.

Baseline rule AUDITED

Reason code stale_page_ctr_gap: flags content where days_since_last_update >= 180, impressions_90d >= 500, 0 < avg_position <= 20, and ctr < 0.5. Before use, both signals behind this rule were independently verified:

  • MIXED Staleness vs. decline rate rose from 51.2% (n=20,655, <90 days) to 61.1% (n=9,171, 90–180 days) — but reversed to 47.1% (n=174, 180+ days), a real pattern, not sampling noise. Likely explanation: the most stale content may have already bottomed out.
  • CONFIRMED CTR by position tier, after a data-quality fix (see Limitations): median CTR at position 20+ (0.08) is roughly half that of the 11–20 tier (0.17), confirming the expected relationship once low-volume outliers were filtered.

Validation design

A client-grouped split (80/20, GroupShuffleSplit) was used, guaranteeing zero client overlap between training and test sets — verified directly, not assumed. This directly addresses a risk surfaced in the baseline audit, where one client accounted for 6 of the top 10 flagged pages.

Leakage audit FOUND & QUANTIFIED

impressions_90d structurally overlaps the label's own 30-day definition window. Removing it dropped AUC from 0.604 to 0.551 — confirming partial, not total, leakage: the remaining 0.551 is still real signal from the other eleven features. The model was also confirmed to use no future-window or internal product-computed fields (e.g. FlyRank's own health score or optimization flags) as inputs.

Error analysis

On the held-out test set: 1,281 false negatives (missed declines) and 1,308 false positives (flagged non-declines) — a roughly balanced error profile, with no strong systematic bias toward either error type at the default 0.5 threshold.

05 Limitations & Honest Framing

01

Single historical snapshot. This dataset represents one point in time for one portfolio collection; findings are not validated across seasons, industries, or content types beyond what's represented here.

02

Bulk-update artifact FOUND & FLAGGED. A systematic check found 23 clients (55.8% of all rows) show a near-uniform days_since_last_update value — almost certainly a migration or mass-republish date, not genuine editorial activity. Bulk-event rows show a modestly higher decline rate (56.3% vs. 51.6%) than unaffected rows; every row is tagged with a bulk_event_flag so this can be excluded or controlled for in any downstream use.

03

CTR unit-scale bug FIXED. 1,689 rows stored click-through rate on a 0–100 scale instead of 0–1 (confirmed by cross-checking against raw clicks_90d/impressions_90d), producing mathematically impossible values above 1.0. All CTR values were recomputed directly from raw clicks and impressions before scoring.

04

Non-monotonic staleness signal. Staleness predicts decline up to ~180 days, then reverses for more extreme staleness — likely because heavily stale content has already bottomed out. The rule and model may both under-flag the most extreme staleness cases as a result.

05

Partial feature leakage. impressions_90d contributes some predictive power via structural overlap with the label's own definition window (a 0.053 AUC contribution) — real signal remains without it, but this should be disclosed alongside any feature-importance ranking.

06

Not validated for new clients. The client-grouped split evaluates generalization across established clients only; performance on a brand-new client with no historical data in this dataset is untested.

No-go — never automate these

  • Never auto-publish, auto-delete, or auto-redirect a page based on this score alone.
  • Never apply this queue to legal, medical, financial, or other YMYL content without senior editorial and subject-matter review, regardless of score.
  • Never treat risk_score as a per-page guarantee — it is a portfolio-ranking signal (AUC 0.604), not a certainty for any individual page.
  • Never act on a stale_* reason code for any row with bulk_event_flag = true without manually confirming the page's real last-edit date first.
  • Never apply this model to a brand-new client with no historical data — it was validated on established clients only.
